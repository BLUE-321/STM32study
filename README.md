# STM32 + FreeRTOS 姿态感知与舵机控制

基于 STM32F103C8、FreeRTOS、MPU6500 和 OLED 的嵌入式学习项目：采集加速度，估算俯仰角，经低通滤波后控制舵机，并记录传感器任务的周期统计。

本次源码同步来源为学习过程中上传的 `main.c`。它将仓库原来的 AX 单轴映射版本更新为三轴加速度俯仰角控制版本；其他驱动与工程配置沿用仓库现有文件。本次未读取开发者电脑上的完整本地工程。

> 本项目是姿态感知与舵机联动实验。当前角度来自加速度计的重力方向估算，适合静态或缓慢运动场景；尚未实现陀螺仪融合、PID 闭环或完整飞控。

## 已实现功能

- 软件 I²C 读取传感器加速度与陀螺仪原始数据；当前控制算法使用三轴加速度。
- 采集与控制分为两个 FreeRTOS 任务。
- 长度为 1 的结构体队列配合 `xQueueOverwrite()`，保留最新加速度数据。
- 使用 `atan2f()` 与 `sqrtf()` 估算俯仰角，进行一阶低通滤波。
- TIM2_CH3 输出舵机 PWM，加入限幅、死区和单次变化量限制。
- OLED 显示滤波角度及 PWM，串口输出调试数据。
- 保存前 10 个有效任务周期，计算最小值、最大值、总和及平均值，只统计一次。

## 任务与数据处理

| 任务 | 优先级 | 栈深度 | 职责 |
| --- | --- | --- | --- |
| `Task_ReadSensor` | 2 | 256 words | 周期记录、传感器读取、覆盖队列、延时 |
| `Task_ControlServo` | 4 | 512 words | 等待队列、角度计算、滤波、PWM 与显示输出 |

栈深度是 FreeRTOS 的栈元素数量；本 Cortex-M3 移植的栈元素为 32 位。

采集任务发送 `SensorData_t { ax, ay, az }`，控制任务通过 `xQueueReceive(..., portMAX_DELAY)` 等待新数据。控制任务优先级更高，采集任务的实际周期会受到其执行时间及其他中断、调度影响。

俯仰角计算：

```text
pitch = atan2(-ax, sqrt(ay² + az²)) × 180 / π
filtered_pitch = 0.65 × previous_pitch + 0.35 × current_pitch
```

首次滤波直接采用当前角度。角度限制在 −90°～+90°，再线性映射到 500～2500 μs 的 PWM 脉宽。当前死区为 8 μs，单次输出变化上限为 80 μs。以实际执行代码为准，部分历史注释尚未同步参数。

TIM2 的配置按定时器时钟 72 MHz 计算：预分频 71，重装载 19999，计数步长 1 μs，PWM 周期 20 ms（50 Hz）。更换时钟配置后需要重新核算。

OLED 和串口输出在处理新数据时检查 100 ms 的刷新间隔，并非独立的严格 10 Hz 显示任务。

## 编译与下载

1. 克隆仓库：
   ```bash
   git clone https://github.com/BLUE-321/STM32study.git
   ```
2. 使用 Keil µVision 打开根目录的 `pojiect.uvprojx`。
3. 工程目标为 STM32F103C8，记录的编译器为 ARM Compiler 5.06 update 7，器件包为 `Keil.STM32F1xx_DFP.2.2.0`。若本机没有相同环境，先安装或调整对应配置；切换编译器后需重新验证。
4. 在 Debug 选项中选择 ST-Link，并确认 SWD 连接及 Flash 下载算法。
5. Build 或 Rebuild，检查编译与链接结果，再 Download 到开发板。
6. 运行后缓慢倾斜传感器，观察 OLED 角度、PWM 与舵机响应。串口使用 115200、8N1。

软件 I²C 使用 `RTOS_Delay_us()` 忙等待，未占用 FreeRTOS 的 SysTick；其延时受时钟、编译优化和抢占影响，并非经过标定的精确微秒定时。

## 周期统计与调试

当前配置 `configTICK_RATE_HZ = 1000`，因此 1 Tick 对应 1 ms。

采集任务在每次循环开头读取 Tick，跳过首次无前驱样本的差值，随后保存 10 次有效差值：

| 变量 | 含义 |
| --- | --- |
| `debug_delta_tick` | 相邻两次循环开头的 Tick 差值 |
| `tick_history[10]` | 首批 10 个有效周期 |
| `history_index` | 已保存数量，满后保持 10 |
| `min_tick / max_tick` | 最小、最大周期 |
| `sum_tick / avg_tick` | 总和、平均周期 |
| `statistics_done` | 统计完成后置 1 |

`history_index == 10` 后停止记录和重复统计，传感器读取、队列发送及任务延时继续执行。

任务末尾使用 `vTaskDelay(pdMS_TO_TICKS(10))`。这不是严格的 10 ms 采样周期：记录值还包含任务执行、抢占及调度等影响，也不能直接当作传感器读取耗时。

调试流程：

1. 下载后用 Ctrl+F5 进入调试模式。
2. 在传感器读取处设置断点，按 F5；记录满 10 条后仍反复命中，说明循环继续运行。
3. 在 Watch 中查看上表变量，局部变量需要在合适的函数作用域内观察，优化可能影响其可见性。
4. 测量实际周期时清除断点、复位并连续运行，再暂停查看已保存的数组。

例如，若样本恰为 8 个 26 Tick 和 2 个 33 Tick，则最小值 26、最大值 33、总和 274、平均值约 27.4。此处是算法校验示例，不是本次提交的实测性能结论。
